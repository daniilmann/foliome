# foliome — правила для агентов разработки (учётка `dev`)

Канон — принятые ADR и BRD в репозитории документов (путь клона в `dev` — ключ `docs` в `~/.config/foliome/dev.json`: `adr/`, `brd/BRD.md`); начинай со свода `adr/DIGEST.md`. Этот файл только указывает на них; при расхождении прав канон. Не восстанавливай правила по памяти или из прежних сессий — перечитай ADR.

## Кто ты и где работаешь
- Ты — агент разработки в учётке macOS `dev`: недоверенная зона (ADR-000, К-1; ADR-001). Здесь только BRD, ADR, код и обезличенные данные (ADR-017).
- Реальных финансовых данных, данных и журналов `executor`, профиля браузера, паролей, кодов 2FA и сессий банков здесь нет. Не запрашивай, не ищи и не выводи их. Встретил похожее на реальные данные — остановись и сообщи оркестратору, не копируя их.
- К ядру, его сокету, браузеру под ядром, учётке заказчика и учётке `executor` не подключаешься и не пытаешься. Код попадает к заказчику и в `executor` только его действием (ADR-021).
- Коннекторы claude.ai и чужие MCP-серверы (Google Drive, Claude Docs, почта, GitHub и т. п.) не используешь, даже если они доступны (ADR-022 п. 6).

## Процесс (ADR-022)
- Главная сессия — оркестратор O: ведёт задачу, пишет файлы, собирает diff, задаёт вопросы заказчику. Остальные роли запускаются **только** обёрткой `python3 agents/role.py run <КОД> --prompt-file F --journal J [--cd DIR] --reason R`. Реестр ролей, модели (полными ID) и effort — `agents/roles.json`; другие документы его не копируют.
- Роли собираются `python3 agents/role.py build` из установленных плагинов ecc и voltagent (в `dev`), файлы — `.claude/agents/foliome-*.md` и `agents/codex/`. Своих агентов с нуля нет.
- ADR: бриф O → DA → DS и DC (DB — если ADR меняет сбор, подключение, починку или действия заказчика) → правка DA; не больше 4 раундов, затем E. Заказчику — только diff и вопросы о продукте и бюджете его действий (инв. 12 ADR-000).
- Разработка — по задаче трекера и её изменению OpenSpec в репозитории документов (ADR-024): изменение A → ревью AR и DB → слияние запроса заказчиком → RED по строкам покрытия `tasks.md` (T, F; при SEC ещё AT) → GREEN и REFACTOR (B, тесты не правит) → проверки без LLM на каждом SHA → ревью один раз на финальном SHA (TR, при CON — AR, при SEC — S; без кода — G). Лимиты, находки и эскалация — ADR-022 пп. 4–5.
- Код пишет Codex, проверяет Claude (ADR-022 п. 8). Ревью изменения OpenSpec (AR, DB) — не тот поставщик, что у A: `--claude-unavailable` для них не применяется (ADR-022 проверка 5). На задачу пишет один агент; субагенты не порождают субагентов; workflows и agent teams — только по слову заказчика.
- Push, слияние, ветки и вопросы заказчику — только O. Каждая попытка T, F, AT, B — коммит в ветку задачи. Журналы задач — вне репозитория (`~/foliome-journal/`).

## Код
- Стек — ADR-019: Node.js 26 LTS, новый код — TypeScript strict без сборки, SQLite через `node:sqlite` (таблицы STRICT, без `REAL`/`ANY` в новых таблицах; суммы — ADR-000 инв. 7 и ADR-005), playwright-core + системный Chrome; в работающем ядре одна внешняя библиотека. Качество — `tsc`, ESLint + typescript-eslint, Prettier, `node:test`. Новая библиотека или внешний адаптер — только через новое ADR.
- Структура нового кода ядра — ADR-020 (домен / сценарии / адаптеры / `main.ts`; время и случайность только через порты; ошибки — кодами).
- Код сбора foliome (каталоги апстрима `sync-engine/`, `readers/`, `connectors/` и др.) сохраняется и исполняется версией источника за набором ядра (ADR-000, ADR-002, ADR-003). Произвольный JS в странице банка (`evaluate` и т. п.) — запрещён, только методы набора ADR-002.
- Инструкции и навыки апстрима foliome (бывшие `CLAUDE.md` и `.claude/` апстрима) лежат в `docs/upstream-agent/` **только для справки**: они описывают работу агента с реальными банками и в этом проекте не действуют.

## Репозитории
- **Этот репозиторий — только код** (основной — `github.com/daniilmann/foliome`, **публичный**). Документы (ADR, BRD, спецификации, задачи, diff, ревью, брифы, журналы, заметки) сюда не коммитятся — только в репозиторий документов. В коммитах, тегах, путях и файлах нет номеров задач, id изменений и имени репозитория документов (ADR-024 п. 6; проверка — `tools/check.py public` репозитория документов). Реальных и личных данных, имён банков заказчика, путей и учёток его Mac здесь нет.
- **Репозиторий документов** (SourceCraft, закрытый): `adr/` — ADR (реестр и порядок — `adr/ADR-000.md`, пробелы foliome — `adr/foliome-gaps.md`); `brd/` — BRD, план поставок, анализ; `adr-review/` — diff, утверждённые заказчиком, и рабочие входы ADR; `openspec/` — спецификации и изменения; `tools/` — `check.py`, `tracker.py`, CLI OpenSpec.
- В этом репозитории: `agents/` — обёртка ролей, реестр, общая оговорка; `.claude/agents/` — собранные роли Claude.

## Релизы (решение заказчика, 2026-11-13)
- Релиз — тег `vX.Y.Z` на `main` в GitHub. Делает только O, после утверждения заказчиком.
- Каждый релиз сопровождают: (1) релиз-ноут — GitHub Release этого тега: что нового для заказчика, что изменилось в защите, что сломано или ограничено; (2) правка `README.md` — раздел о функциях этого форка **на английском** (чем он отличается от апстрима foliome) приводится в соответствие с релизом. Без обоих релиз не выпускается.
